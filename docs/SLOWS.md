# Independent movement slows

`World.applySlow(source, target, kind, durationTicks, startMultiplier, endMultiplier?)` applies or refreshes an independently saved contribution. A multiplier is the fraction of movement speed retained. Constant slows use equal endpoints; an increasing multiplier models a slow that weakens linearly. The API rejects invalid or external units, allied/structural/dead/invulnerable recipients, incompatible champion/effect identities, invalid durations and out-of-range strengths. Dead champion sources remain valid for committed effects.

Current effect identities are `frost`, `critical-frost`, `crystal-arrow` and `lucent`. Refresh replaces only the same source/effect pair. Source death leaves existing contributions intact. Target death and respawn clear them. Expiry removes contributions before commands and movement on the deadline tick. Refresh timing and linear decay remain explicit adapter policies pending native comparison, as described in [Frost Shot](FROST-SHOT.md).

The movement resolver evaluates every active contribution and uses the minimum speed multiplier, without multiplying simultaneous slows. Weaker contributions continue counting down while suppressed and take effect if they outlast a stronger contribution. Linear effects compete at their current strength, so a constant slow may become dominant before the linear effect ends. Heal haste still applies through the existing movement calculation.

Ashe combat now records ordinary Frost, champion Volley critical decay and primary R slow separately. Different Ashes cannot erase one another's contributions. R splash retains the existing ordinary Frost strength and duration policy. This change corrects overlap; it does not re-audit those ability-specific values.

Legacy `slowUntil`, `slowMultiplier` and `criticalSlow` fields remain for existing diagnostics and latest-hit inspection, and also participate in the minimum calculation. Existing combat fills them alongside the new contributions; duplicate representation never multiplies the slowdown. New persistent effects must use the contribution API. These legacy fields are not a complete slow history and must not be used as the displayed effective slow; overhead status, HUD speed and run playback use the shared resolver. A future schema cleanup can remove the diagnostic compatibility fields after the remaining fixtures are migrated.

Snapshot 42 requires contributions and validates source champion identity, enemy living nonstructural recipients, unique source/effect pairs, active start/end ticks and valid strength curves. It preserves weaker suppressed effects through restoration. Movement-speed soft caps, slow resistance, tenacity, removal/cleanse rules and native reapplication exceptions remain unfinished. Lux E has a supported `lucent` contribution identity but its field and recast lifecycle remain unimplemented.

Validation: 557 checks pass, including six new scenarios for independent expiry/save continuation, curve overlap, source/effect refresh and death, real high-/low-level Ashe Volley overlap, invalid API calls and malformed saves. Four focused Chrome cases validate effective movement readouts, independent slow expiry/status and animation scaling. Production build and nested-path smoke pass. Full browser, match and performance suites were not repeated.
