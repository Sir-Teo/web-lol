# Development Leona support trial on the Rift

During development, `/?scene=leona-rift` starts Leona in the human support slot of
an actual Rift lane match. The loaded source map, navigation, brush, height,
structures, lane waves, jungle camps and visibility queries remain the Rift's.
The factory replaces the allied Lux support, retaining the other four allied
bots, five opponents and all ten role assignments. The human receives no automatic
lane order or skill allocation and starts with one unspent point.

The host adds a trusted `developmentLeona` battlefield capability. It is never
serialized into a save. Construction and spawning accept Leona in that context;
strict decoding permits her Rift records only in lane mode. A normal battlefield
still rejects a trial save, even if its file attempts to supply the capability.
Garen and the ordinary Ashe/Lux champion chooser retain their existing gates.
The production build ignores this development scene and champion query.

The trial uses the separate `development-leona-rift` browser checkpoint slot for
Save, restart, import and new matches. It preserves the ordinary `rift` slot.
Restart recreates Leona support with the chosen summoners and unlearned kit.
Choosing Ashe or Lux in the ordinary new-match menu is respected after reload;
those matches continue using the trial's separate slot while that URL is open.
Exported files identify the real Rift battlefield, so loading a Leona trial file
requires this development context.

This establishes a normal-map development entry and saved integration. It does
not establish full roster release, a normal-match cohort, performance acceptance,
native frame/listening equivalence or the three unresolved R effect families.

## Verification

Two pre-implementation regressions reproduce the constructor/spawn gates. Six
new simulation cases use the actual retained Rift navigation bytes and layout.
They check all ten roles, source query identity, 22 turrets, paid/unlearned input,
all nine bot paths plus human movement, independent Leona bot learning, strict
context gates and exact saved futures.

The first expanded fixture requested Exhaust, which is outside the implemented
Flash/Heal/Smite loadout; the corrected case uses Heal/Flash. A typecheck also
caught direct access to the private champion registry in a test. Removing an
inactive unit already excludes its record from snapshots, so that access was
removed without changing the simulation registry.

The full standard check passes 2,034 units in 328 files, TypeScript and three
Node QA checks. All four new Chrome cases pass, then pass again in the broader
88-case run with no skipped, flaky or failing cases. Real keyboard input learns
and pays for Q. Movement checks the actual source terrain for the human and all
nine bots, and the full-map capture was visually reviewed. Save/reload preserves
the exact checkpoint and 400-tick future. Real Save/restart/new-match controls
retain support identity, preserve the ordinary slot and honor a later Lux choice.
An ordinary page rejects a trial save without replacing its stored bytes.
